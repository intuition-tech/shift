# Вёрстка публикаций

Как устроены публикации на сайте, как их верстать и как переносить со старого сайта. Общее устройство проекта — в [README](../README.md), живые образцы всех компонентов со списком классов — на `/design-system/`.

Прежде чем верстать, откройте 2–3 готовых гайда: [order-in-projects](../src/pages/order-in-projects.html) (типовой), [saving-printed-layouts](../src/pages/saving-printed-layouts.html) (нумерованный список с картинками в пунктах), [dubai-dodo-pizza-mena-2025](../src/pages/dubai-dodo-pizza-mena-2025.html) (слайды, палитры, видео, page-local стили).

## Структура публикации

Каждый гайд — один файл `src/pages/<slug>.html` с фронтматтером и инлайновым переключением языка. URL плоские: `/<slug>/` и `/en/<slug>/`.

```html
---
title: Название — Shift
titleEn: Title — Shift
description: "…"
tags: guide
---
<div class="ids__space XL"></div>
<article class="ids__wrapper guide">
  <div class="guide__nav"><ids-navbar></ids-navbar></div>   <!-- если есть разделы -->
  <h1>{% if lang == 'ru' %}…{% else %}…{% endif %}</h1>
  {% include "pub-meta.html" %}                              <!-- дата и теги из src/data/publications.js -->
  <p class="ids__description">…</p>                          <!-- лид -->
  <ids-nav-item id="слаг-раздела" label="Название раздела">
    <h2 class="h3">…</h2>
    …
  </ids-nav-item>
  <div class="ids__space L"></div>
</article>
```

Оглавление строится само из `<ids-nav-item>`. Якоря разделов — **осмысленные слаги** (`#small-formats`), а не порядковые номера, как было на старом сайте (`#n0`): номера ломаются при вставке раздела в середину.

У каждой публикации должна быть запись в `src/data/publications.js` (оттуда таблица на главной и мета-блок под h1 берут заголовок, дату и теги). При переносе гайда со старого сайта перезаписывайте его страницу-заглушку и меняйте `status: "stub"` на `"published"` в данных.

## Компоненты и стили

Разметка собирается из компонентов IDS — их перечень с образцами на `/design-system/`. **Новый компонент сразу добавляется туда**, иначе следующий человек напишет его заново под другим именем.

Локальные компоненты живут в `static/css/components/` с префиксом `ids__`. Внутри компонента размеры в `em` (масштабируются от кегля), на уровне композиции — в `rem`. Цвет — только через семантические токены (`--ids__text`, `--shift__dodo-orange`); новое значение сперва заводится в палитре `tokens/palette.css`, потом получает семантическое имя в `tokens/colors.css` или `tokens/shift.css`.

Page-local `<style>` допустим для того, что не покрыто компонентами (специфичная таблица, подсветка сегментов), но классы — с префиксом страницы. Если то же самое понадобилось второй раз, это уже компонент: заводите его в `components/` и показывайте на `/design-system/`.

### Грабли, на которые уже наступали

- **Нативный CSS-нестинг не умеет конкатенацию `&---mod`** — это привычка из Sass. Модификаторы с длинными суффиксами пишутся полными селекторами (см. [no-yes.css](../static/css/components/no-yes.css)); иначе правило молча не применяется.
- **Инлайн-блоки `.ids__no-yes` ставятся вплотную**: пробел между `</div>` и `<div>` считается за ширину и ломает строку. В разметке они склеиваются комментарием: `</div><!--\n  --><div…`.
- **YAML во фронтматтере**: значение с двоеточием (`description: Алгоритм: 3 шага`) роняет сборку — берите в кавычки.
- **`{% %}` исполняется и внутри HTML-комментариев** — незакрытый тег Nunjucks там сломает сборку.
- **Не собирайте путь к файлу шаблоном** (`src="/images/x/{% if lang == 'ru' %}1.jpg{% else %}1-en.jpg{% endif %}"`): такие пути не переживают автоматических замен при оптимизации картинок. Дублируйте внутри `{% if %}` весь тег целиком.

## Картинки

Складывать в `static/images/<slug>/`, путь в разметке — `/images/<slug>/…`. Внешние URL (Cloudinary и прочие) оставляем внешними.

**Оптимизируйте до коммита.** Материалы обычно приходят неадекватными по весу: фотографии по 6000 px, которые рисуются в 460, фото в PNG, GIF-анимации по 8 МБ. Порядок:

```
npm run build
python3 -m http.server 8091 --directory site &   # нужен для замера
node tools/measure-images.mjs                    # с какой шириной что рисуется
python3 tools/optimize-images.py                 # ресайз + WebP + GIF → mp4
python3 tools/optimize-images.py --fix-links     # правит ссылки в разметке
npm run build
```

Что за этим стоит:

- целевая ширина — **2× от фактической ширины отрисовки** (ретина). Текстовая колонка 960 px, значит потолок для картинки во всю ширину — 1920 px, а для `figure.ids__media XS` (184 px) — 368 px;
- **WebP** для фото и скриншотов, но палитровые PNG (плоская графика, интерфейс с малым числом цветов) часто уже легче WebP — скрипт такие оставляет, и это правильно;
- **GIF всегда переводится в mp4**: те же кадры весят в 10–15 раз меньше. `<img>` заменяется на `<video src="…" autoplay loop muted playsinline>`, в медиа-контейнерах IDS видео уже стилизовано как картинка;
- `--fix-links` не видит пути, собранные шаблоном, — их правят руками (см. грабли выше).

Исходники после оптимизации не храним: они есть в старом репозитории, при необходимости пересохраним оттуда заново.

## Перенос со старого сайта

Старый сайт — `/Users/arutyunov/dbdt` (Express + Pug + SCSS), контент вшит в Pug с миксинами `+ru`/`+en`. Список публикаций и их статусы — в CSV «Shift — All Guides», переносим помеченные «Актуально».

Переносится **живой** контент страницы, дословно и целиком. Не переносится:

- закомментированные блоки Pug (`//` и `//-`) — в старых гайдах их много, иногда половина файла;
- теги тем, подборок, авторов, хлебные крошки, блоки «Читать далее» — таких сущностей на новом сайте пока нет;
- `+es` (испанская локаль) — её не поддерживаем;
- обвязка старого шаблона: `.guide-nav-wrapper`, `.guide-body-wrapper`, `.mobile-breadcrumbs`, `block topicTags/peopleTags`.

Пустой `+en` означает «перевода нет»: пишите русский текст без условия, английская страница покажет его же. Не переводите сами и не сокращайте — опечатки исходника тоже переносятся как есть.

Старые классы не переносятся, разметка перекладывается на компоненты IDS.

**Картинки копируйте пофайлово.** В папках старого сайта лежат черновики, отброшенные варианты и картинки прошлых редакций: при копировании папки целиком (`cp -R`) в репозиторий приезжают десятки мегабайт мусора — так уже случилось однажды, вычищали потом отдельно. Копируйте ровно те файлы, на которые ссылается живая разметка.

## Проверка перед коммитом

```
npm run build                    # без ошибок
```

Затем на локальном сервере: битые локальные ссылки (собрать все `href`/`src` со страниц и проверить, что файлы существуют), консоль браузера, 404 в сети и глазами — несколько страниц с самыми сложными компонентами. Ссылки на ещё не перенесённые гайды в 404 — это ожидаемо, всё остальное — нет.

Не коммитьте `site/` (в гитигноре) и не оставляйте временные файлы в `static/`.
