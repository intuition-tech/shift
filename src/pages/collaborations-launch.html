{% if lang == 'ru' %}Запуск{% else %}Launch{% endif %}

{% include "pub-meta.html" %}

{% if lang == 'ru' %}Первый день продаж: сверяем факт с планом, держим команды наготове и разбираем остатки в пиццериях.{% else %}The first day of sales: we check actuals against the plan, keep teams ready and sort leftovers in pizzerias.{% endif %}

{% if lang == 'ru' %}Когда продукт, продвижение и операционная подготовка уже собраны, начинается запуск. Это первый день продаж.{% else %}Once the product, promotion and operations prep are in place, launch begins. It is the first day of sales.{% endif %}

{% if lang == 'ru' %}Прогноз, расчёт волны спроса и работа с аналитиками к этому моменту уже сделаны на этапе подготовки. Здесь держим наготове поддержку и операционку, сверяем продажи с планом и с первого дня управляем остатками в пиццериях.{% else %}The forecast, the demand-wave calculation and the work with analytics are already done at the preparation stage. Here we keep support and operations ready, check sales against the plan, and manage leftovers in pizzerias from day one.{% endif %}

{% if lang == 'ru' %}Прогнозы сейчас считают вместе с аналитиками так, чтобы спрос не выходил за заложенные рамки. Если спрос всё же сильно превысил ожидания, управляющей компании, возможно, придётся помочь пиццериям. Например, отключить доставку на всех точках.{% else %}Forecasts are now built with analytics so demand stays inside the frame we set. If demand still far exceeds expectations, the management company may have to help pizzerias. For example, by switching delivery off at every site.{% endif %}

{% if lang == 'ru' %}Проверяем готовность команд{% else %}Check that teams are ready{% endif %}

{% if lang == 'ru' %}К первому дню продаж клиентская поддержка, поддержка партнёров и операционка на местах уже должны быть готовы. Что именно им готовить — людей, статью для пиццерий и стандарты — разбираем на этапе реализации, в блоке про операционную подготовку.{% else %}By the first day of sales, customer support, partner support and operations on the ground must already be ready. What to prepare for them — people, the pizzeria article and standards — is covered at the implementation stage, in the operations-preparation block.{% endif %}

{% if lang == 'ru' %}У клиентской поддержки должны быть выделены люди, чтобы отвечать на большое количество вопросов от гостей. У партнёров, пиццерий, есть своя поддержка. Туда они обращаются с вопросами и получают быстрый ответ. Операционка на местах тоже должна быть готова.{% else %}Customer support must have people assigned to answer a large volume of guest questions. Partners, the pizzerias, have their own support. They write there with questions and get a fast answer. Operations on the ground must also be ready.{% endif %}

{% if lang == 'ru' %}Менеджер и команды поддержки готовятся к старту, даже если лавинообразного спроса уже не ждут. Если спрос всё же сильно превысил ожидания, управляющая компания может помочь пиццериям, в том числе отключить доставку.{% else %}The manager and the support teams prepare for the start even if an avalanche of demand is no longer expected. If demand still far exceeds expectations, the management company can help pizzerias, including by switching delivery off.{% endif %}

{% if lang == 'ru' %}Ведём канал для управляющих{% else %}Run the channel for managers{% endif %}

{% if lang == 'ru' %}Помимо поддержки, в большом Telegram-канале управляющих создаём отдельную ветку под проект, который стартует. В день запуска туда дополнительно приходит много вопросов, и менеджеру нужно на них отвечать.{% else %}On top of support, in the large Telegram channel for managers we create a separate thread for the project that is going live. On launch day a lot of extra questions arrive there, and the manager needs to answer them.{% endif %}

{% if lang == 'ru' %}Менеджер отвечает не на все вопросы по смежным темам. Это могут быть вопросы по упаковке или по отгрузке: не приехала, что делать. Менеджер координирует и подключает ответственных коллег, если те долго не отвечают.{% else %}The manager does not answer every question that belongs to a neighbouring topic. These can be questions about packaging or a shipment: it did not arrive, what to do. The manager coordinates and brings in the colleagues responsible if they are slow to reply.{% endif %}

{% if lang == 'ru' %}Отслеживаем продажи и корректируем коммуникацию{% else %}Track sales and adjust communication{% endif %}

{% if lang == 'ru' %}В первый день продаж смотрим, как факт сходится с планом. Для этого к запуску нужна таблица, по которой отслеживаются продажи.{% else %}On the first day of sales we see how actuals meet the plan. For that we need a table by launch that tracks sales.{% endif %}

{% if lang == 'ru' %}Её готовит команда аналитиков. Менеджер заранее приходит к ним и просит составить самообновляющуюся таблицу исходя из плана на коллаборацию. Продажи день в день система не показывает. Цифры можно увидеть только на следующий день.{% else %}The analytics team prepares it. The manager comes to them in advance and asks for a self-updating table based on the plan for the collaboration. The system does not show same-day sales. The numbers appear only the next day.{% endif %}

{% if lang == 'ru' %}Таблица нужна, чтобы решить, усиливать продвижение и подключать дополнительные источники коммуникаций или, наоборот, сократить и перенести уже запланированные анонсы и дополнительные активности. Если продажи сильно превысили прогноз, давление коммуникаций снижаем. Если недобрали, коммуникацию усиливаем.{% else %}The table tells us whether to strengthen promotion and add extra communication sources, or to cut and postpone announcements and extra activity already planned. If sales have far exceeded the forecast, we ease the pressure of communication. If we undershot, we strengthen it.{% endif %}

{% if lang == 'ru' %}Вот пример такой таблицы.{% else %}Here is an example of such a table.{% endif %}

{% if lang == 'ru' %}Небольшое отклонение от плана — нормальная часть запуска. Если в первый день вместо 90 000 продали 10 и на следующий день картина не меняется, включаем то, что хотели поставить на позже.{% else %}A small gap from the plan is a normal part of launch. If we sell 10 on day one instead of 90,000 and the picture does not change the next day, we turn on what we had meant to schedule for later.{% endif %}

{% if lang == 'ru' %}Решения принимаем в моменте. Готового списка «если так, сделай так» нет: для каждого проекта решение своё. Запуск готовим по плану продвижения в заданных каналах. Если видим, что распродадимся очень быстро, встречаемся с лидером и внутренним отделом и решаем, какие из запланированных активностей не проводить. Дополнительные активности берём из того, что уже подготовили: чтобы не повторяться, найти другое решение или усилить собранное.{% else %}We decide in the moment. There is no ready list of “if this, do that”: each project needs its own decision. We prepare the launch against a promotion plan in set channels. If we see we will sell out very fast, we meet the lead and the internal team and decide which planned activities not to run. Extra activity comes from what we already prepared: so we do not repeat ourselves, find another solution, or strengthen what we built.{% endif %}

{% if lang == 'ru' %}Подсказываем пиццериям сценарии{% else %}Scenarios for pizzerias{% endif %}

{% if lang == 'ru' %}Остатками нужно управлять с первого дня. В статье для пиццерий заранее пишем, что делать в каждом сочетании: закончилась только упаковка, только мерч, один ингредиент или весь продукт.{% else %}Leftovers have to be managed from day one. In the pizzeria article we write in advance what to do in each combination: only packaging has run out, only merch, one ingredient, or the whole product.{% endif %}

{% if lang == 'ru' %}В коллаборации Winx для этого собрали таблицу сценариев по четырём позициям: брелок, коробка, брусничный соус и чизибайтсы. Отдельно в ней указано, что делать с коммуникацией в трейде. Списание больших остатков на РЦ разбираем на этапе постанализа.{% else %}In the Winx collaboration we built a scenario table for this around four items: keychain, box, lingonberry sauce and cheesy bites. It also says what to do with trade communication. Writing off large leftovers at the DC is covered at the post-analysis stage.{% endif %}

{% if lang == 'ru' %}Если ни один сценарий нельзя закрыть. В коллаборации Winx оставляли отдельный путь для невскрытых упаковок: возврат на РЦ. Возвращали только невскрытые позиции, через претензию в личном кабинете поставщика. Как это делать, описано в гайдбуке по работе с Восток-Западом. Сроки возврата в каждом запуске свои. Их прописываем в статье для пиццерий. Вскрытое так не вернуть.{% else %}If none of the scenarios can be closed. The Winx collaboration kept a separate path for unopened packs: a return to the DC. Only unopened items could be returned, through a claim in the supplier account. How to do it is described in the East-West working guidebook. Return dates are specific to each launch. We write them in the pizzeria article. Opened packs cannot be returned this way.{% endif %}

{% if lang == 'ru' %}Если сценарии в пиццериях не сработали и большие остатки мерча или упаковки всё равно лежат на РЦ, а не в точках, дальше идёт списание за счёт бюджета управляющей компании. Как запускать процесс, что делать с продуктовыми остатками и кто принимает решение, разбираем на этапе постанализа.{% else %}If the pizzeria scenarios do not work and large leftovers of merch or packaging still sit at the DC, not in the shops, write-off against the management company’s budget comes next. How to start the process, what to do with product leftovers and who decides is covered at the post-analysis stage.{% endif %}

{% if lang == 'ru' %}Параллельно с продажами с первого дня собираем материалы запуска.{% else %}In parallel with sales, from day one we collect the launch materials.{% endif %}

{% if lang == 'ru' %}Собираем материалы с запуска{% else %}Collect the launch materials{% endif %}

{% if lang == 'ru' %}Они нужны для отчётности, для работы с брендом и для лицензиара.{% else %}They are needed for reporting, for work with the brand and for the licensor.{% endif %}

{% if lang == 'ru' %}Что собираем. Все скрины запуска и полезную информацию, которая потребуется затем. Например, как выглядело размещение рекламы. Снимаем видео того, как запуск выглядит в приложении. Заходим в карточку продукта и снимаем её анимацию.{% else %}What we collect. Every launch screenshot and the useful information we will need later. For example, how the advertising placement looked. We film how the launch looks in the app. We open the product card and capture its animation.{% endif %}

{% if lang == 'ru' %}Куда складываем. В одно место по ходу проекта, а не в конце. В коллаборации Winx это собирали на холсте. Потом в любом случае понадобится либо кейс, либо внутренняя презентация, и лучше, чтобы все данные уже лежали вместе. Туда же можно подгружать результаты. Иначе потом не собрать ни кейс, ни отчёт.{% else %}Where we keep it. In one place as the project runs, not at the end. In the Winx collaboration this was collected on a canvas. A case or an internal presentation will be needed anyway, and it is better if all the data already sits together. Results can be loaded there too. Otherwise neither the case nor the report can be assembled later.{% endif %}

{% if lang == 'ru' %}Параллельно аналитики на своём этапе могут считать эффект. Сам расчёт относится к этапу постанализа, но материалы для него копятся с первого дня.{% else %}In parallel, analytics can count the effect at their own stage. The calculation itself belongs to the post-analysis stage, but the materials for it accumulate from day one.{% endif %}
