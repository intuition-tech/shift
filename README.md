# Shift

Двуязычный статический сайт на [Eleventy 3](https://www.11ty.dev). Русская версия в корне, английская — под `/en`.

## Запуск

```
npm install
npm run dev     # http://localhost:8080
npm run build   # сборка в site/
```

## Структура

```
eleventy.config.js   # конфиг Eleventy (ESM): фильтры pub, tagName, formatDate…
src/pages/           # страницы: .html с фронтматтером + Nunjucks
src/pages/pages.11tydata.js  # двуязычная генерация: каждая страница собирается в / и /en
src/data/            # данные: publications.js (мастер), authors.js, taxonomy.js, promo.js
src/includes/        # layout.html, header.html, footer.html, pub-meta.html, people.html, stub-note.html
src/styles/site.css  # стили сайта поверх IDS → /assets/site.css
src/scripts/main.js  # кука переключателя языка → /assets/main.js
static/              # копируется в корень сайта как есть
site/                # результат сборки (в гитигноре)
```

## Дизайн-система IDS

В `static/css`, `static/js`, `static/fonts` лежит копия [IDS](https://github.com/intuition-tech/ids) (снепшот от 2026-08-26, версия 1.0), **перестиленная под дизайн старого сайта Shift** (shift.dodobrands.io): шрифты Pragmatica + Elma Trio, цвета и кегли старого сайта, флюидная рампа 13→23 px (desktop) / 17→26 px (mobile). По философии IDS система не подключается как зависимость, а копируется и правится в проекте.

Что изменено и добавлено относительно ванильной IDS:

- `tokens/palette.css` — базовый слой: статичные значения цвета старого сайта, названные по оттенку и весу (`--ids__color-navy-900`, `--ids__color-orange-500`…), двумя группами — универсально-интерфейсные и брендовые Shift (додо-оранжевый и плашки промоблоков); в компонентах напрямую не используются; порядок объявления = порядок на витрине;
- `tokens/colors.css` — семантические цвета IDS, только ссылки на палитру;
- `tokens/shift.css` — семантические токены, специфичные для Shift (`--shift__brand` — додо-оранжевый, `--shift__aside-background`, `--shift__shadow-color`, `--shift__billet-under`, `--shift__promo-*`, `--shift__description-font`) — тот же слой, что colors.css;
- `settings.css` — @font-face старых шрифтов и рампа со старыми числами;
- `components/ids.css` — типографика по старым кеглям (h1 3.23em/650, h2 2.5em/570, `h2.h3`, `h2.special`, списки, таблицы, `aside`, `figcaption`, `.lead`, `.ids__description`, `.ids__table-wrapper`);
- новые локальные компоненты: `components/media.css` (`.ids__media`, `.ids__media-group`), `components/no-yes.css` (`.ids__no-yes`, `.ids__billet`), `components/note.css` (`.ids__with-note`, `.ids__note` — сноска на полях), `components/video.css` (`.ids__video`, iframe или `<video>`), `components/report.css` (`.ids__report-header`, `.ids__portraits` — отчёты Meme Park), `components/color-palette.css` (`.ids__color-palette`, `.ids__copy`, `.ids__icon-set` — копирование цвета/SVG, JS в `js/copy.js`), `components/checklist.css` (`.ids__checklist`), `components/slide.css` (`.ids__slide`, `.ids__slide-pair`), `components/download.css` (`.ids__download`, JS в `js/download.js`), `components/promo-link.css` (`a.ids__promo-link` — пилюля с толстым подчёркиванием, ссылка на внешний файл), `components/compare.css` (`.ids__compare`, JS в `js/compare.js`), `components/style-guide.css` (витрина); модификаторы `.ids__sequence` — `.no-wrap`, `.tight`, `.labels`, `.labels.yes-green` в `page-composition/layout.css`; `gallery.css` — превью 8em как в старых отчётах;
- `components/navbar.css` — `ids-navbar` — оглавление публикации в левом поле (sticky, ширина по длиннейшему пункту, прижат к колонке; скрыт < 768px). Слева от текущего пункта — черта-индикатор `.ids__navbar-indicator`: `js/navbar.js` (перенос nav-indicator с arutyunov.info) двигает её по скроллу между якорями разделов, по клику — перелёт к пункту, по ховеру красится; тот же пункт получает класс `current` (старый scroll-spy IDS по центру секции отключён — два алгоритма показывали разные пункты). Композиция колонки публикации (`.publication`, `.publication__nav`) — локальный `page-composition/publication.css`;
- `components/anchor.css` + `js/anchor.js` — ссылка на любое место публикации: блокам тела статьи раздаются id по хэшу содержимого; из левой трети колонки над блоком слева сразу появляется иконка-цепь (без задержки — она читалась как медленный сайт; из правых двух третей не появляется, чтобы не мелькать при чтении), показанная следует за курсором по блокам по всей ширине колонки и гаснет с фейдом 0,3 с, когда курсор выходит из колонки и её левого поля (всё по координатам `mousemove`, без таймеров); в левом поле блок берётся по вертикали через `elementFromPoint` — так ссылку получает и `iframe` (`.ids__video`), над которым родительский документ событий мыши не видит; клик копирует URL с якорем, переход по нему (после доскролла) обводит угол блока оранжевым «маркером» — рукописным эллипсом 2:1 (`--shift__brand`, поверх хедера). Зазор между оглавлением и иконкой — правый паддинг `ids-navbar`;
- `components/pill.css` — пилюля `.ids__pill` (`.outline`, `.ids__pill-photo` с заглушкой `.initial`, `.ids__pill-count`): общий формфактор тегов мета-блока, тегов-фильтров, даты, кнопки «Все публикации» и людей; содержимое по базовой линии, интерлиньяж 1.6 = высота фото. `components/people.css` — блок «Люди»;
- стрелки «НЕТ/ДА» — `static/images/no-yes/`.

Внимание: нативный CSS-нестинг не умеет Sass-конкатенацию `&--mod` — модификаторы с длинными суффиксами пишутся полными селекторами (см. `no-yes.css`).

Порядок подключения CSS в `src/includes/layout.html` нормативный: tokens → settings → reset → page-composition → components.

Тем нет: сайт только светлый, блок `.dark` из ванильной IDS удалён вместе с цветами, которые жили только в нём. Если тёмные публикации понадобятся — тема добавится слоем в `tokens/colors.css` (`theme-toggle.css/js` лежат в `static/`, но не подключены).

Неиспользуемые на Shift компоненты ванильной IDS удалены из копии: `gen-cover.css/js` с демо `gen-cover-demo.js` (генеративная обложка) и `promo-block.css/js` (инлайн-галерея `.ids__inline-gallery`; наши промоблоки — в `promo-grid.css`). Понадобятся — берутся заново из репозитория IDS. Демо-скрипт `sleepy.js` лежит в `static/`, но не подключён.

Структура публикации, компоненты, работа с картинками, правила переноса со старого сайта и грабли — в [docs/content-markup.md](docs/content-markup.md). ## Публикации

Каждая публикация — один файл `src/pages/<slug>.html` с фронтматтером (`title`/`titleEn`, `description`/`descriptionEn`, `tags: publication`) и инлайновым переключением языка `{% if lang == 'ru' %}…{% else %}…{% endif %}`. URL плоские: `/<slug>/` и `/en/<slug>/`. Разделы оборачиваются в `<ids-nav-item id="слаг" label="…">` — из них строится оглавление. Картинки — в `static/images/<slug>/`, оптимизированные (WebP, анимации — mp4; см. [docs/content-markup.md](docs/content-markup.md)).

### Данные публикаций

Мастер-данные всех публикаций — `src/data/publications.js`: слаг, заголовки, дата, авторы (контактное лицо — флагом `contact`, обязан входить в `authors`), теги (рынки, команды, предметные области, подборки — слаги из `src/data/taxonomy.js`), ручной флаг «новое» `isNew`, статус `published | stub | external`. Справочник авторов — `src/data/authors.js` (имена английские, фото в `static/images/authors/`). Порядок тегов в `taxonomy.js` = порядок групп в таблице. Данные правятся руками; заголовки страниц дублируются во фронтматтере (он остаётся для `<title>`/OG), слаг связывает.

Данные были сгенерированы одноразовыми скриптами: `tools/import-csv.mjs` (из CSV «Shift — All Guides»; даты — из последних коммитов гайдов в dbdt) и `tools/make-stubs.mjs` (страницы-заглушки для неперенесённых гайдов — реальный URL, h1, мета-блок, ссылка на старый адрес; перенос гайда = перезаписать файл и сменить `status`). Команды в данных — плейсхолдеры, разложены эвристикой по областям.

### Главная и /publications/

Главная — не то же, что «Все публикации»: основная колонка (`.ids__wrapper` без модификатора — доля `--ids__column` в `layout.css`, 63%, та же, что у текста публикации; от неё же считается левое поле под оглавление) с крупным поиском, группой «Всегда под рукой» (пины читателя, см. ниже; появляется, когда есть пины), блоком «Новое» (`isNew`; строки визуально не отличаются — новизну показывает заголовок блока), под таблицей по центру — контурная пилюля «Все публикации» (`.ids__pubs--all`, контур как линейка между строками; строкой таблицы она читалась как часть контента); затем сетка промоблоков в широком враппере `.ids__wrapper.M` (подборки + рынок MENA; конфиг с колонками, цветами и описаниями — `src/data/promo.js`, счётчики считаются на сборке; сквиркл 2.9em — в браузерах без `corner-shape` SVG-маски режут угол жёстче, там радиус на четверть больше), блок «Люди» и блок контактов со ссылкой на тг-канал Shift. Крупный поиск — пилюля (`border-radius` у `.search--large .search-line`), свешивается за края колонки на 0,3 rem. Полной таблицы на главной нет, фильтров тоже.

Блок «Люди» (инклюд `people.html`, стили `components/people.css`) — все авторы, у которых есть публикации: фильтр `people` в `eleventy.config.js` считает их по `publications.js` (справочник `authors.js` шире — люди без публикаций не выводятся), по алфавиту; каждый — пилюля с фото (или заглушкой-буквой) и числом публикаций, ведёт на `/publications/?author=…`; заголовок «Авторы всех публикаций» Элмой как у группы таблицы, число при нём — обычным шрифтом, серым (на старом сайте было 56: там считался весь справочник, включая людей без актуальных гайдов). Тот же блок — страница `/people/` (`src/pages/people.html`, над ним обычный h1 «Люди»), на неё ведёт последний пункт меню «Люди» (активный — по `page.filePathStem`).

Полная таблица живёт на `/publications/`: все публикации по дате, фильтрация (автор, рынок, команда, область, подборка, новизна) и группировка (рынки, команды, подборки — ссылки в хедере) — `static/js/pubs-table.js`; состояние целиком в URL (`/publications/?market=russia`, `/publications/?group=teams&area=smm`). Под h1 — теги-фильтры по рынкам и командам (обычные ссылки из шаблона; скрипт перехватывает клик, активный тег — с крестиком-SVG, выровненным по центру заглавных через базовую линию пилюли, один за раз); показываются только на «Всех публикациях» без группировки и без фильтра по автору. Над таблицей — чип для остальных активных фильтров (автор, область, подборка, новизна): кнопка-пилюля того же кегля, что люди на главной, у автора с фото (карта фото — в JSON-острове), клик снимает фильтр; при фильтре по автору группа «Всегда под рукой» не показывается. Фильтр включается и тегами на страницах публикаций (мета-блок `pub-meta.html` под h1; ответственный помечен «Оунер»). Активный пункт хедера — болдом, h1 повторяет пункт меню (ставит `pubs-table.js`).

Поведение строк (везде, где есть `.ids__pubs`; `pubs-table.js` подключается в самой странице сразу после таблицы, а не в лейауте — иначе пины появляются с миганием после первой отрисовки): ссылкой работает вся строка — переход по клику на `data-href` делает скрипт (оверлей-псевдоэлемент не годится: Safari не делает `tr` containing block), настоящая ссылка — название, авторы — текстом через запятую, каждое имя кликабельно отдельно. Булавка справа (по ховеру строки, по фокусу, на таче всегда) — **личный пин читателя**: слаги в `localStorage` (`shift:pins`), закреплённые публикации собираются копиями строк в группу «Всегда под рукой» вне зависимости от фильтров; исходная строка остаётся на месте и меняет состояние там, куда смотрит читатель. На главной группа стоит в той же таблице перед «Новым», на `/publications/` (`data-pins="separate"`) — отдельной табличкой со спейсером, а основная таблица без группировки получает заголовок «Всё-всё-всё». Иконка булавки — инклюд `pin-icon.svg`, «втыкание» анимируется в CSS. Редакторских пинов в данных нет. Компоненты — `components/pubs.css`, `components/pub-meta.css`, `components/pill.css`, `components/promo-grid.css`, образцы на `/design-system/`. Компонент `button.css` удалён вместе с кнопкой на главной.

Контент переносится со старого сайта `/Users/arutyunov/dbdt` (Pug, миксины `+ru`/`+en`). Список публикаций и их статусы — CSV «Shift — All Guides». Перенесены 33 из 35 актуальных гайдов.

Не перенесены:

- «Визуальный стиль Додо Пиццы» (`/graphic-design/brandbook-dodo-pizza` → исходник `graphic-design/visual-style-dodo-pizza.pug`, 2117 строк и 185 МБ картинок) — отложен, пока заглушка `/visual-style-dodo-pizza/`;
- гайды в статусе «Обновить» — у них страницы-заглушки со ссылкой на старый адрес (`status: "stub"` в `publications.js`);
- «Процессы и инструменты команды Stories In App» и «Перед началом работы» — внешние ссылки на buildin.ai, отдельных страниц сайта нет, в таблице открываются в новой вкладке.

## Поиск

Клиентский поиск, портирован с arutyunov.info (там обкатывался как прототип). Три части:

- `src/pages/search-index.11ty.js` — на сборке пишет полный двуязычный индекс `{url, lang, title, text}` в `/search-index.json` и `/en/search-index.json` (оба файла одинаковые: поиск с любой страницы находит оба языка; клиент берёт файл своего раздела). Текст — очищенный `templateContent`, так что гайды находятся и по именам авторов и тегам из мета-блока. Исключение страницы из индекса — `searchIndex: false` во фронтматтере (стоит на главной, `/publications/`, `/people/`, `/design-system/`). Для этого в `pages.11tydata.js` включён `addAllPagesToCollections` — иначе в коллекции попадает только RU-проход.
- `static/js/search.js` — движок (стеммеры Портера/Snowball для EN/RU, матчинг «все слова по стему, последнее ещё и по префиксу», сниппеты с подсветкой) и выпадайка-комбобокс. Инстансов на странице может быть несколько (шапка + образцы на витрине), индекс грузится один раз.
- `src/includes/search.html` + `static/css/components/search.css` — поле. В шапке внутренних страниц маленькое (на мобильных — второй строкой), на главной вместо него крупное `.search--large` в начале контента. Выпадайка одна, вся вёрстка в em — крупность задаётся кеглем на корне `.search`.

## Дизайн-система /design-system

`/design-system/` — витрина (по образцу ponedelnik.ru/style): палитра и семантические токены дампятся из живого CSS скриптом `static/js/tokens-dump.js` (слоты `data-tokens-prefix` / `data-tokens-render`); типографика — таблицей «элемент / образец / токены»; компоненты — блоками «табличка название+токены → образец на всю ширину → список мест использования (фильтр `usages` в `eleventy.config.js`, строится на сборке) → спейсер». Новые компоненты сразу добавляются сюда. В навигацию не выводится, доступна по прямой ссылке.

## Двуязычность

Каждая страница в `src/pages` собирается дважды через pagination по `locales` (`pages.11tydata.js`): русская в корень, английская с префиксом `/en`. Внутри шаблона язык переключается инлайново: `{% if lang == 'ru' %} … {% endif %}`. Переключатель в футере ведёт на парную страницу (`otherLangUrl`) и запоминает выбор в куке `_int_locale`.

## Деплой

GitHub Pages: пуш в `main` запускает `.github/workflows/deploy.yml` — сборка Eleventy и публикация `site/` через `actions/deploy-pages`. В настройках репозитория Pages должен быть в режиме «GitHub Actions».
